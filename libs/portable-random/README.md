# portable-random

`lambdaseq/portable-random` provides secure randomness through `portable.random`.
JVM Clojure, Babashka, Node, and browsers share the same byte and integer contracts.
The library has no runtime dependency beyond Clojure. The `lambdaseq/portable` umbrella includes it.

```clojure
(require '[portable.random :as random])

(def data (random/generate-bytes! 32))
(count data)                         ; 32
(random/generate-bytes! 0)           ; []
(random/generate-int! 1)             ; 0
(random/generate-int! 65536)         ; integer from 0 through 65535
```

## API contract

| Function | Input | Result |
| --- | --- | --- |
| `generate-bytes!` | Integer byte count from 0 through 1048576 | Immutable vector of unsigned byte integers |
| `generate-int!` | Integer upper bound from 1 through 9007199254740991 | Uniform integer from 0 inclusive to the upper bound exclusive |

Both functions are synchronous side effects. Host entropy acquisition can block.
Byte vectors use the same representation as [portable-bytes](../portable-bytes/README.md).
The byte count is capped at 1 MiB. Integer bounds fit JavaScript's safe integer range on every runtime.
Bound 1 always produces 0. Secure source availability is checked even for bound 1 or a zero-byte request.
These trivial requests consume no random bytes.

Integer sampling uses the same algorithm on every runtime.
It draws enough random bits, masks unused high bits, and rejects candidates outside the requested range.
Every accepted integer has equal probability. Values beyond 32 bits retain their exact integer representation.
After 128 rejected draws, sampling throws `:rejection-limit` instead of returning a biased value or looping indefinitely.
Seeding and entropy management belong to the platform source.

## Platform sources and failures

| Runtime | Secure source |
| --- | --- |
| JVM, Babashka | Lazily initialized, shared `java.security.SecureRandom` |
| ClojureScript, Node | `node:crypto.randomFillSync`, using the CommonJS `:nodejs` target |
| ClojureScript, browser | `globalThis.crypto.getRandomValues` |

The adapter uses the [JVM secure generator](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/security/SecureRandom.html)
and [Node's synchronous fill API](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptorandomfillsyncbuffer-offset-size).
Browser fills use views of at most 65536 bytes to respect the [Web Crypto quota](https://www.w3.org/TR/webcrypto/#Crypto-method-getRandomValues).
Larger public requests are filled in consecutive views of one private buffer.
Native buffers remain private. A failed fill throws without returning partially generated data.
Secure platform entropy is mandatory; missing support and native failures fail explicitly.

Errors use `ex-info` with the qualified `:operation` and a `:reason`:

| `:type` | Reasons |
| --- | --- |
| `:portable/invalid-input` | `:invalid-byte-count` or `:invalid-upper-bound` |
| `:portable/unsupported-operation` | `:secure-random-unavailable` |
| `:portable/random-error` | `:entropy-failure` or `:rejection-limit` |

Input validation precedes source access. Native failure causes are retained.
Error data excludes generated bytes. This API exposes neither callbacks nor native source objects.

## DNS and verification

`portable-dns` uses `generate-int!` with upper bound 65536 for transaction IDs.
The shared API replaces DNS's private generator. An ID is drawn once and reused across UDP-to-TCP fallback.
Entropy failures reach DNS's error callback before socket creation. Browser DNS codecs remain independent of entropy availability.

```sh
clojure -T:build test :modules :portable-random
clojure -T:build jar :modules :portable-random
clojure -T:build test :modules :portable-dns
```

Shared contracts cover real native sources, request limits, safe integer boundaries, and deterministic rejection paths.
Exhaustive small sample spaces verify equal accepted outcome counts without flaky statistical thresholds.
Failure contracts verify missing sources, retained causes, retry limits, and browser quota handling.
These checks verify the API and sampling algorithm; source security relies on the platform implementation.
Tests are excluded from library jars.

Verification uses macOS, Clojure 1.12.4 on JDK 25.0.3, Babashka 1.13.219, ClojureScript 1.11.132, Node.js 24.22.1, and Chrome 157.0.8103.80.
Linux, Windows, Firefox, Safari, browser workers, ClojureCLR, ClojureDart, and jank remain unverified.
